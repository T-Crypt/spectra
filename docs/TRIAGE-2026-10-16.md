# Issue triage, 2026-10-16

This note covers the repository issue list and the follow-ups the 2026-10-16 quality pass left open.

## Open issues

`gh issue list --state open` returns nothing. `gh issue list --state all` also returns nothing, so the repository has no issues, open or closed, at this date. There is nothing to rank, assign, or close. The rest of this note records what the pass found, so nothing is lost.

## Fixed on this pass

- The build backend in `pyproject.toml` named `setuptools.backends._legacy:_Backend`, a module that does not exist, so `pip install .` and every wheel build failed. It now names `setuptools.build_meta`. A wheel builds and the `spectra` console script installs.
- The test count in `docs/DESIGN.md` and `docs/MILESTONE-1.md` was stale. Several claims in `docs/MILESTONE-1.md` also disagreed with the code: enum serialization, the `Run.to_json` method names, the `python -m spectra` invocation, a `tests/test_reference_sm89.py` that does not exist, and the throttle fact names. All now match the code.
- `docs/EVAL.md` gave the roof rule predicate as `objective_ratio >= 0.9`. The implemented rule also requires `objective_ratio <= 1.0`.

## Follow-ups not fixed here

1. `docs/EVAL.md` sections A9 and E0 still present the speculative-factor conflict as open. They set the counter ratio 1.6635 against the implied 1.97. The code settled it with a third derivation, the round rule `committed / (committed - accepted)`, which gives 3.0195 for the recorded counters and is pinned by `tests/test_analyze.py`. EVAL.md is a dated research design. Its owner should revise the narrative, not a quality pass.
2. No linter is configured or documented. CI runs only `python -m unittest discover -s tests`. Adding one is a deliberate choice, and this pass did not make it.
3. The live NVML and engine tests ran on this machine and passed. The three skips were the opt-in live fidelity and eval stages. Nothing in this pass depends on that result.
